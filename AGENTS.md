# loclizr

A compiler for the contract between code and translations. `loclizr build` reads JSON catalogs at
`locales/{locale}.json`, lowers every message to one IR, and writes typed ESM message functions plus a
context record (`locales/loclizr.context.json`). Catalog checks run inside the build and are on by
default. App code is never transformed and the compiler never writes catalogs.

`docs/design/spec.md` is the binding contract: signatures, rule codes and file paths there win over
anything else, this file included.

## Invariants

1. The browser never ships an ICU parser; parsing is build time only.
2. Generated code imports only `loclizr` and its own sibling files.
3. The locale is resolved at call time, so switching needs no reload.
4. No mutable global locale on the server; requests are scoped with `AsyncLocalStorage`.
5. Output is a deterministic function of the inputs: no timestamps, absolute paths, version stamps or iteration-order dependence.

Breaking one before 1.0 is a minor version plus a changelog entry.

## Layout

| Path | What it is |
| --- | --- |
| `packages/loclizr` | The SDK. Entries `loclizr`, `loclizr/react`, `loclizr/server`, `loclizr/compiler`; bin `loclizr` |
| `examples/*` | One app per framework (`vite-react`, `svelte`, `vue`, `solid`, `astro`, `vanilla`), built against the package's public entries |
| `apps/web` | Docs site: Astro Starlight with `starlight-theme-black`, deployed to GitHub Pages |

## Modules

Paths under `packages/loclizr/src`. Each path belongs to one module, and a module never edits another's
files. A test that needs another module's behaviour uses a local double under its own `__fixtures__/`.

| Module | Path | Role |
| --- | --- | --- |
| contracts | `types.ts`, `diagnostics/`, `util/` | shared types, the rule table, helpers |
| catalog | `catalog/` | load JSON catalogs, i18next import |
| icu | `icu/` | parse ICU, lower to IR nodes |
| analyze | `analyze/` | build the message IR |
| check | `check/` | verification rules |
| emit | `emit/`, `test/typecheck-fixture/` | print ESM functions and `.d.ts` text |
| scan | `scan/` | tokenizer scan for usage sites |
| record | `record/` | the context record |
| config | `config/` | load and validate `loclizr.config.ts` |
| compiler | `compiler/`, the package's build and test config | the pipeline; the only place severities are re-levelled |
| cli | `cli/` | `init`, `build`, `check` |
| runtime | `index.ts`, `runtime/`, `react/`, `server/` | locale store, React hook, server scoping |

Modules emit diagnostics at the rule's default severity and never read `config.severity`.

## Commands

```sh
pnpm install && pnpm build && pnpm install --offline   # fresh clone: the second install links the loclizr bin for examples and apps/web
pnpm test                                              # SDK tests
pnpm --filter loclizr exec vitest run src/<module>     # one module
pnpm check                                             # the gate CI runs; green before calling anything done
```

## Toolchain

- TypeScript 7 strict with `isolatedDeclarations`, `verbatimModuleSyntax`,
  `exactOptionalPropertyTypes` and `noUncheckedIndexedAccess`. Every export has an explicit type.
- Built with tsdown. Tests are vitest, colocated as `*.test.ts`.
- Imports inside `src` are extensionless; generated output uses `.js` because Node resolves it in SSR.
- ESM only, Node 20.19+, pnpm 9. The SDK's dependency list is frozen; a new dependency needs a reason.

## Docs site

- Pages live in `apps/web/src/content/docs`; the sidebar in `apps/web/sidebar.ts`.
- The site compiles its own catalogs with loclizr (`apps/web/locales`, 13 locales). A new site string
  needs all 13 or the build fails.
- Each page is also served as Markdown, and `llms.txt` lists them.
- Site widgets call messages with `{ locale }` per call and never `setLocale`, so the English docs keep
  `<html lang="en">`. React widgets mount from a plain script, not a `client:*` island: the `llms-full.txt`
  route renders pages without a React renderer.
- Every transcript or generated block in the docs is pasted from a real run.
- `src/loclizr/` folders (site and examples) are generated by `loclizr build`; never edit them.

## Writing about loclizr

Lead with the build gate and the types. Do not claim per-locale delivery (every locale is inlined
today), stability (it is 0.x), or a context record richer than it is. Out of scope for 0.1: runtime
`format()`, string extraction, first-class Next.js, URL-prefix routing, `--watch`.

## Conventions

- Conventional Commits, one concern per commit, `pnpm check` green before it lands on `main`.
- Comments say why, not what. No em or en dashes in code, docs or commits.
