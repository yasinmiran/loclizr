```txt title="npx loclizr --help"
loclizr <command> [options]

Commands
  init     write loclizr.config.ts and a seed catalog, then print the
           package.json scripts and the CI step
  build    read the catalogs, check them, write the generated tree and the
           context record
  check    everything build does with no writes, plus the output and record
           gates

Options
  --cwd <dir>             directory to run in, default the current one
  --config <path>         config file to load, or the one init writes
  --reporter human|json   diagnostic format, default human
  --max-warnings <n>      exit 1 above this many warnings, --max-warnings=-1
                          for no cap, which is also the default
  --quiet                 print errors only, plus a summary line when warnings
                          were dropped
  --no-fail               build only: report everything, exit 0 once output
                          was written
  -h, --help              print this
```

The binary is `loclizr`, from the package of the same name, run as `npx loclizr` or through a
`package.json` script. One help text serves all three commands: no `--version`, no per-command
help, and `loclizr build --help` prints the block above.

Every sample here comes from the [example app](https://github.com/loclizr/loclizr/tree/main/examples/vite-react)
catalogs (`en.json`, `en.meta.json`, `de.json`, a sparse `de-AT.json`) with
`groups: { errors: 'errors' }` in the config. Where a sample shows an error, the edit that
produced it is named.

## Commands

### `loclizr init`

```txt title="npx loclizr init, in an empty directory"
wrote loclizr.config.ts
wrote locales/en.json

Install loclizr, which loclizr.config.ts imports:

  npm i -D loclizr

Add these scripts to package.json:

  "prepare": "loclizr build --no-fail",
  "predev": "loclizr build --no-fail",
  "prebuild": "loclizr build",
  "pretypecheck": "loclizr build"

Add this step to CI:

  # loclizr check compares the committed context record against this tree.
  # loclizr build would rewrite that record in the CI workspace and pass.
  - run: npx loclizr check
```

- Writes `loclizr.config.ts` and, under the default catalog layout, `locales/en.json`.
  Create-only: an existing file is left as it was, and the output says so.
- Prints an install note, the scripts and a CI step rather than editing `package.json`.
- Takes `--cwd` and `--config`. `--no-fail` is a usage error.

Before writing, `init` looks for catalogs on disk and reports them
(`found 3 locales at locales/{locale}.json: de, de-AT, en`). What it finds decides the config:

- No source catalog, or an empty one, is greenfield and gets
  `severity: { 'ambiguous-source': 'error' }`, so the gate is hard from the first commit. Existing
  catalogs get the same line commented out, with the note below saying when to turn it on.
- An existing generated tree in the workspace (a `messages.js` with the generated header, outside
  `node_modules`, `dist`, `build` and the declared `outDir`) adds `augmentLocale: false` with a
  comment, since two trees augmenting the locale registry in one TypeScript program is TS2717.
- Catalogs laid out another way, say `public/locales/{locale}/{ns}.json`, become the `catalogs`
  pattern and the seed file is skipped: a demo `locales/en.json` beside a real tree would compile
  the demo strings and hide every real catalog.

The seed catalog is ICU, its plural written `{count, plural, one {...} other {...}}` rather than
`_one` / `_other`, so it stays ICU under the default `catalogFormat: 'auto'` even once an imported
i18next file lands beside it. The config never carries a `catalogFormat` line.

### `loclizr build`

```txt title="npx loclizr build, first run"
warn  LZ4006  group-args-heterogeneous

  The group "errors" has members with different argument sets, so every dynamic call site must pass the union: seconds.

    errors.forbidden       takes no arguments
    errors.not_found       takes no arguments
    errors.rate_limited    takes seconds

  fix  Split the group by argument shape, or give the odd members bare {x} arguments.

wrote src/loclizr (21 files) and locales/loclizr.context.json
commit locales/loclizr.context.json; `loclizr check` compares it
26 messages, 3 locales (source en), 0 errors, 1 warning
```

Reads the catalogs, lowers every message, runs the whole rule set, scans the sources for usage
sites, writes the tree under `outDir` and the record beside the catalogs.

- Files are written only when their bytes changed, and the summary counts them. An unchanged
  second run prints the same diagnostic and counts and no `wrote` line.
- Then it prunes: files under `outDir` carrying the generated header that this emit did not
  produce are deleted, so a renamed top-level key leaves no `messages/old.js` behind. A file
  without the header is never touched and is reported as `LZ1021 outdir-foreign-file`.
- Non-fatal errors still emit: a missing German translation writes `messages.js` anyway, fills
  the message from the fallback chain, prints `LZ3001`, exits 1, and the summary adds
  `fell back to source text: de 1`. Fatal diagnostics (identifier collision, no catalogs, invalid
  config) write nothing.
- The only command that takes `--no-fail`.

### `loclizr check`

Everything `build` does with no writes, plus two gates against the committed tree, which makes it
the CI command. Here `cart.greeting` was edited in `en.json` after the last `build`:

```txt title="npx loclizr check, after editing en.json"
error  LZ5002  output-stale  src/loclizr/messages/cart.d.ts

  `src/loclizr/messages/cart.d.ts` differs from what this build would write.

  fix  the generated tree on disk is stale; run `loclizr build`.

error  LZ5002  output-stale  src/loclizr/messages/cart.js

  `src/loclizr/messages/cart.js` differs from what this build would write.

  fix  the generated tree on disk is stale; run `loclizr build`.

error  LZ5003  record-stale  locales/loclizr.context.json

  `locales/loclizr.context.json` no longer matches the catalogs: the contract this build derived differs from the committed record.

  fix  run `loclizr build` and commit the record with the string change.

warn  LZ4006  group-args-heterogeneous

  The group "errors" has members with different argument sets, so every dynamic call site must pass the union: seconds.

    errors.forbidden       takes no arguments
    errors.not_found       takes no arguments
    errors.rate_limited    takes seconds

  fix  Split the group by argument shape, or give the odd members bare {x} arguments.

26 messages, 3 locales (source en), 3 errors, 1 warning
```

| Gate | Fires when |
| --- | --- |
| `LZ5002 output-stale` | a generated file on disk differs from what this build would write, or is an orphan carrying the header |
| `LZ5003 record-stale` | the committed context record differs from the one these catalogs produce |

- On a tree that was never built, `LZ5003` says the record does not exist and was never committed.
- `LZ5002` fires only for files on disk, so a gitignored `outDir` that a CI checkout lacks raises
  nothing.
- `--no-fail` is refused:

```txt
loclizr: --no-fail is not accepted by `loclizr check`, which is the gate
```

## Options

Options are global and go after the command. `parseArgs` from `node:util` parses them, so
`--max-warnings 0` and `--max-warnings=0` are the same thing.

| Option | What it does |
| --- | --- |
| `--cwd <dir>` | Project root: where the config is looked for, and the base of every config and diagnostic path. Default: current directory. Missing or not a directory: usage error, exit 2. |
| `--config <path>` | Config file, relative to `--cwd`. Default: the first of `loclizr.config.ts`, `loclizr.config.mts`, `loclizr.config.js`, `loclizr.config.mjs`; none at all means defaults. A path naming no file: `LZ1001 config-invalid`, exit 2. |
| `--reporter human\|json` | Diagnostic format. Anything else: usage error. |
| `--max-warnings <n>` | Exit 1 when warnings exceed `n`. Absent or negative: no cap, so warnings alone never fail a run. Non-integer: usage error. |
| `--quiet` | Errors only. The summary line stays when it accounts for hidden warnings, so a run that exits 1 on `--max-warnings` still says why. No effect on the JSON reporter. |
| `--no-fail` | `build` only. Same diagnostics, exit 0 once output was written. Below. |
| `-h`, `--help` | The usage block, exit 0, with or without a command. |

Colour is used when stdout is a TTY and `NO_COLOR` is unset. Piped output, and CI, get plain text.

## `--no-fail`

The dev loop's flag. Diagnostics, re-levelling, sort order, the record rewrite and `LZ5007` are
all as without it; a `build` that got as far as writing output exits 0 instead of 1. Both runs
below started from identical copies of the example with `cart.greeting` deleted from `de.json`.

One code moves, and only downward:

- Exit 2 is untouched: the tool could not run, so there is nothing to keep working with.
- No output still exits 1. After an identifier collision or a missing source catalog there is no
  tree, `vite dev` is about to fail on the missing module anyway, and a 0 would be a lie the next
  command uncovers.
- A write-if-changed run that wrote zero bytes still reached the write step, so a clean rebuild
  is 0.
- The gate never takes it: [the scripts below](#the-scripts-init-prints) put it on `prepare` and
  `predev` only.

## Exit codes

| Code | Meaning |
| --- | --- |
| 0 | Clean, or warnings only and at or under `--max-warnings`. Also any `build --no-fail` that reached the write step. |
| 1 | At least one error, or warnings over `--max-warnings`. |
| 2 | The tool could not run. |

Exit 2 has a closed list of causes:

- `LZ1001 config-invalid`, `LZ1007 outdir-unsafe` and `LZ5001 output-unwritable`: the three rules
  `severity` cannot re-level.
- A usage error: an unknown command or option, `--no-fail` on `check` or `init`, a bad
  `--reporter` value, a non-integer `--max-warnings`, a `--cwd` that does not exist.
- An `init` that could not write one of its two files.
- Anything that threw unexpectedly, printed as `loclizr: <message>` on stderr.

```txt title="exit 2 from a config that names an un-relevelable rule"
error  LZ1001  config-invalid  loclizr.config.ts

  `severity` cannot re-level `config-invalid`.

  fix  LZ1001 decides whether the tool can run at all, so turning it down would let a broken build exit 0.
```

Warnings and `--max-warnings` decide between 0 and 1 only. Eighteen of the fifty-six rules default
to `warn`, which is why the default of no cap decides whether a freshly imported i18next catalog
exits 0 or 1 on its first build.

## Reporters

Both print the same diagnostics in the same order: errors first, then by code, file, locale, key
and offset. Paths are POSIX and relative to the project root on every machine, so the sort is
stable between a laptop and CI.

### Human

```txt title="LZ3012, after adding an undescribed footer.cart beside app.cart and nav.cart"
error  LZ3012  ambiguous-source  locales/en.json:5:14

  3 keys share the source text "Cart" and one has no description.
  A translator sees one string with no way to tell the meanings apart.

    app.cart       locales/en.json:5:14      "Heading over the cart panel. A section title, not a link."
    footer.cart    locales/en.json:41:14     no description
    nav.cart       locales/en.json:21:14     "Top navigation link that opens the cart page."

  fix  add descriptions in locales/en.meta.json:
         "footer.cart": { "description": "" }
  or   turn the rule down in loclizr.config.ts:
         severity: { 'ambiguous-source': 'warn' }
```

- One block per diagnostic, a blank line between, the summary last.
- Header: severity, code, rule, then whichever of `file:line:column`, locale and key the
  diagnostic carries, two spaces apart.
- Related locations, when the rule has them: a three-column table.
- `fix`: the rule's hint, a multi-line hint keeping its lines.
- Summary: one line of counts, `27 messages, 3 locales (source en), 6 errors, 1 warning`. On a
  `build`, a `wrote ...` line precedes it when anything was written, plus a reminder to commit the
  record unless an `LZ5007` already says so. `fell back to source text: de 1, de-AT 1` follows it
  when any message resolved all the way to source text.

Keys, source text and file paths all reach a terminal here. Control characters a terminal would
obey print as `<U+009B>` instead, and a newline inside a key collapses to one space so the header
stays one line.

### JSON

```json title="npx loclizr check --reporter json, clean tree"
{
  "schema": 1,
  "diagnostics": [
    {
      "code": "LZ4006",
      "rule": "group-args-heterogeneous",
      "severity": "warn",
      "fatal": false,
      "message": "The group \"errors\" has members with different argument sets, so every dynamic call site must pass the union: seconds.",
      "hint": "Split the group by argument shape, or give the odd members bare {x} arguments.",
      "file": null,
      "locale": null,
      "key": null,
      "span": null,
      "related": [
        {
          "file": null,
          "locale": null,
          "key": "errors.forbidden",
          "span": null,
          "message": "takes no arguments"
        },
        {
          "file": null,
          "locale": null,
          "key": "errors.not_found",
          "span": null,
          "message": "takes no arguments"
        },
        {
          "file": null,
          "locale": null,
          "key": "errors.rate_limited",
          "span": null,
          "message": "takes seconds"
        }
      ]
    }
  ],
  "summary": {
    "errors": 0,
    "warnings": 1,
    "messages": 26,
    "locales": 3,
    "fellBack": []
  }
}
```

One object on stdout, two-space indented, holding `schema`, `diagnostics` and `summary`.
`--quiet` never thins it: the summary counts have to agree with the array beside them.

Every field is present on every diagnostic, `null` where it does not apply:

| Field | Type | Meaning |
| --- | --- | --- |
| `code` | `string` | Stable code, `LZ3001`. |
| `rule` | `string` | Rule name, the key `severity` accepts. |
| `severity` | `"warn"` or `"error"` | After the config's `severity` is applied. |
| `fatal` | `boolean` | Whether the diagnostic blocked emission. |
| `message` | `string` | The body; may contain newlines. |
| `hint` | `string` or `null` | The `fix` text. |
| `file` | `string` or `null` | POSIX, relative to the project root. |
| `locale` | `string` or `null` | The locale concerned. |
| `key` | `string` or `null` | The flat catalog key. |
| `span` | object or `null` | `{ line, column, offset, length }`, 1-based line and column. A missing translation has no span: nothing to point at. |
| `related` | array | `file`, `locale`, `key`, `span` and `message` per entry, the rows the human reporter prints as a table. |

- `summary.fellBack` holds `{ "locale", "count" }` per locale with at least one message resolved
  to source text: `[]` on a clean tree,
  `[{ "locale": "de", "count": 2 }, { "locale": "de-AT", "count": 1 }]` after deleting two German
  strings.
- A run halted by an invalid config reports `"messages": 0` and `"locales": 0`.
- DEL and the C1 control block are escaped as `\u007f` through `\u009f`, so a parser gets the
  catalog's bytes back while a terminal tailing the output cannot be told to move the cursor.

## The scripts `init` prints

```json title="package.json"
"prepare": "loclizr build --no-fail",
"predev": "loclizr build --no-fail",
"prebuild": "loclizr build",
"pretypecheck": "loclizr build"
```

`prepare` runs on install and `predev` before `vite dev`. Their job is to make a generated tree
exist on a fresh clone and at the start of every dev session, and one untranslated key must not
stop the dev server, so they carry `--no-fail`. `prebuild` and `pretypecheck` run in front of the
commands that ship and take the real exit code. Neither is the gate, though.

```yaml title=".github/workflows/ci.yml"
# loclizr check compares the committed context record against this tree.
# loclizr build would rewrite that record in the CI workspace and pass.
- run: npx loclizr check
```

A pipeline whose only invocation is `pnpm build` rewrites the record in the CI workspace and
passes, so a pull request that changed copy without regenerating lands with a stale record.
`check` compares instead of writing, which is why it exists as a separate command.

<Aside type="note">
There is no `--watch`. `nodemon -w locales -x 'loclizr build --no-fail'` gives you the loop, and the
example app ships an inline Vite plugin that reruns the build when a catalog changes.
</Aside>
