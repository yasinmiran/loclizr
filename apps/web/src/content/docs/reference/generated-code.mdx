- JavaScript plus a hand-printed `.d.ts`, never `.ts`, so generated code inherits nothing from
  the host tsconfig (`jsx`, path aliases, `strict`), serves JavaScript consumers without
  `allowJs`, and stays out of the app's typecheck graph. Declarations are printed as text;
  `typescript` is never needed.
- Relative imports carry an explicit `.js`: this code runs under Node during a server render.
- One module per top-level key segment, not one per message and not one flat file. Keys with no
  dot land in `_root`.

### The header line

Every file except the `.gitignore` starts with the same first line, byte for byte:

```js
// @generated by loclizr abi=1. Do not edit; run `loclizr build`.
```

That line is the prune token. After writing, `build` deletes every file under `outDir` that
carries it and that this emit did not produce; a file without it is never deleted or overwritten,
and is reported as `LZ1021 outdir-foreign-file` instead. Files are written only when their bytes
changed.

### The `.gitignore`

```txt title="src/loclizr/.gitignore"
*
!.gitignore
```

- The tree is gitignored through that file, so the root `.gitignore` is never touched and the
  pull request carries the context record, not several hundred lines of machine-written
  JavaScript.
- Written only when absent, and excluded from the write-if-changed comparison and from `LZ5002`.
  A team that commits the tree deletes it once and it stays deleted; `LZ5002 output-stale` then
  checks those files, since the rule fires only for files on disk.

## One message of each kind

Every message function is `f(args, opts?)`, its declaration carrying the source text as a doc
comment. The first parameter is exactly the ICU argument set, so a message with an argument named
`locale` still compiles; the locale override is the second.

```js title="src/loclizr/messages/cart.js"
  const l = $l(opts)
  const n0 = args.count
  switch (l) {
    case 'de':
      if (n0 === 0) return `Dein Warenkorb ist leer`
      return `${$number1(l, n0, $f44136fa355b3678a)} Artikel in deinem Warenkorb`
    case 'de-AT':

      return `${args.count} Artikel im Einkaufswagerl`
    default:
      if (n0 === 0) return `Your cart is empty`

        case 'one':
          return `${$number1(l, n0, $f44136fa355b3678a)} item in your cart`
        default:
          return `${$number1(l, n0, $f44136fa355b3678a)} items in your cart`

  }

```

```ts title="src/loclizr/messages/cart.d.ts"
/** en: "{count, plural, =0 {Your cart is empty} one {# item in your cart} other {# items in your cart}}" */
export declare function cart_items(args: { count: number }, opts?: MessageOptions): string
```

- Exact branches are tested before the category lookup. `Intl.PluralRules` is consulted only when
  a keyword branch renders differently from `other`: the German `one` and `other` bodies are
  identical, so that arm never calls `$plural1`.
- The category follows the body's language and the number follows the visitor's locale. Every
  `$plural1` call names the locale whose text the arm prints, as a literal (`'en'` above); `#`
  goes through `$number1` with the requesting `l` and the empty option set, so
  `m.cart_items({ count: 1234 })` renders `1,234 items in your cart`.
- The `de-AT` arm was `{{count}} Artikel im Einkaufswagerl` in an i18next file. i18next
  stringifies placeholders unformatted, so the conversion keeps `${args.count}` raw rather than
  turning `1000 Artikel` into `1.000 Artikel` on import day.

The literal matters on a fallback arm. A second tree, `locales: ['en', 'fr', 'ja']` with
`{count, plural, one {# active session} other {# active sessions}}` in `en.json` and no
`sessions` in `fr.json` or `ja.json`, prints the English body once. An arm identical to the source arm gets no
`case` of its own, so `fr` and `ja` land in `default:` and their only trace is the `locales`
list in `_locale.js`.

```js title="src/loclizr/messages/_root.js"
export function sessions(args, opts) {
  const l = $l(opts)
  const n0 = args.count
  switch (l) {
    default:
      switch ($plural1('en', n0, false)) {
        case 'one':
          return `${$number1(l, n0, $f44136fa355b3678a)} active session`
        default:
          return `${$number1(l, n0, $f44136fa355b3678a)} active sessions`
      }
  }
}
```

| Call | Renders |
| --- | --- |
| `m.sessions({ count: 0 }, { locale: 'fr' })` | `0 active sessions` |
| `m.sessions({ count: 1 }, { locale: 'ja' })` | `1 active session` |
| `m.sessions({ count: 1234 }, { locale: 'fr' })` | `1 234 active sessions` |

French selects `one` for zero and Japanese selects `other` for everything, so a call that picked
the category with `l` would print `0 active session` and `1 active sessions` against English
text. The grouping in the last row is French, from `$number1(l, ...)`.

### What can throw at run time

The type signature is the only guard. A message function is a template string and a `switch`;
it validates nothing, so a value that arrived from an API is checked at the boundary, not by the
message. Each row ran under Node against the example's tree, locale `en`:

| Call | Result |
| --- | --- |
| `m.cart_greeting({})` | renders `Hi undefined, your cart is ready` |
| `m.cart_items({ count: NaN })` | renders `NaN items in your cart` |
| `m.cart_total({})` | renders `Total: $NaN` |
| `m.order_status({ state: 'nope' })` | renders `Processing`, the `other` branch |
| `m.cart_updated({ at: new Date('nope') })` | throws `RangeError: Invalid time value` from `Intl.DateTimeFormat` |
| `m.terms_accept({})` | throws `TypeError: args.link is not a function` |

The two throws are the two places generated code calls something: `Intl` for a date, and your
tag handler for markup. Everything else interpolates whatever it was given.

## How a call resolves its locale

Every function starts with `$l(opts)`. The resolver is bound to this tree's own `locales` and
`sourceLocale`, and it does one thing:

```ts
matchLocale(opts?.locale ?? getRawLocale(), locales, sourceLocale)
```

- `getRawLocale()` is the store's raw requested tag, unmatched: the active server request scope if
  one is installed, otherwise the tag `setLocale` last stored, otherwise, where a `document`
  exists, the value detected once on first read from the configured cookie and then `<html lang>`.
- The resolver matches that against its own list by exact tag, then by dropping subtags from the
  right, then falls back to the source locale. `{ locale: 'de-CH' }` renders `de`,
  `{ locale: 'sp' }` renders `en`, and nothing requested at all still yields a declared locale.
- Matching against the generated list rather than the store's lets two generated trees with
  different locale sets each resolve correctly from one store.

### Re-rendering on a switch

The per-call `{ locale }` override is a correctness mechanism. A message call is a plain function
call with no subscription in it, so a component that calls `m.cart_items()` and no hook re-renders
only when React re-renders it. Two patterns re-render on a switch:

| Pattern | Effect |
| --- | --- |
| Key the root on `useLocale()` | The tree remounts. |
| Pass `{ locale: useLocale() }` at the call | The component subscribes in place and keeps its state. The locale is a visible reactive dependency, so a memoizing compiler cannot cache the rendered string across a switch. |

## What tree-shakes and what does not

- Message modules are side-effect-free ESM with one `export function` per message. An app that
  imports the barrel and calls three messages ships three functions and the arms of every declared
  locale inside them.
- `_formats.js` constants are annotated pure, so an unused format drops with the last message that
  used it.
- `_locale.js` is retained by any message import, since `$l` is load-bearing, and that is
  intended.
- A group is the one thing that does not shake: `groups.js` builds a frozen object referencing
  every member, so importing `errors` retains all three functions whether or not `errors.forbidden`
  is ever named. Only that group pays, and only in an app that imports `./loclizr/groups`.
- The deep import `./loclizr/messages/cart.js` is the escape hatch where a bundler tree-shakes
  nothing, and the only way to split by hand on React Native, where Metro does not tree-shake.

## Identifiers

`nav.home` becomes `nav_home`. Flat identifiers, never `m.nav.home()`: a namespace object literal
retains every member and kills tree-shaking. Mangling, in order:

<Steps>

1. Normalize the key to NFC.
2. Replace every character that is not `ID_Continue`, `$` or `_` with `_`.
3. Prefix `$` if the result does not start with `ID_Start`, `_` or `$`.
4. Prefix `$` if it is a reserved word, `default` or `then`, since a `then` export makes the module
   namespace thenable and breaks `await import()`.

</Steps>

- An `identifiers` entry in the config replaces the whole result and goes through the last two
  steps too.
- Namespace filenames are mangled the same way, so a key such as `../x.y` cannot write outside
  `outDir`.

### Collisions and reserved names

- Two keys that mangle to one identifier are `LZ4001 identifier-collision`, fatal and never
  auto-disambiguated with a counter.
- `__proto__`, `constructor`, `prototype`, one of the barrel's own exports (`locales`,
  `sourceLocale`, `getLocale`, `setLocale`, `subscribe`), or anything entering the `$` namespace
  is `LZ4002 identifier-reserved`; so is a top-level key segment that would name `_locale`,
  `_formats` or `_root`.
- Doc-comment text is escaped, so a source string containing `*/` cannot terminate the comment
  early.

## Determinism

Emit sorts everything itself, all by code point:

| What | Order |
| --- | --- |
| messages | by key |
| namespaces | by mangled filename |
| hoisted formats | by name |
| group members | by member property |
| groups | by id |
| locale arms | by tag, the source locale always last under `default:` |

It then runs itself a second time over a reversed program and byte-compares. A difference is
`LZ4005 nondeterministic-output`, fatal, and its hint says to report it, because nothing in the
project can be changed to clear it. That check runs on every build, in memory.

The output is a function of these inputs and nothing else:

| Input | What it touches |
| --- | --- |
| the catalogs, the meta sidecar and the config | everything |
| the scanned sources | the record's `usage` entries only |
| the build host's ICU and CLDR data, through `Intl.PluralRules` | which plural categories a locale has: the `=0` or `zero` arm a target locale gets from an i18next `_zero` key, and the `LZ3007` and `LZ3013` category checks |

The last row is the one that can differ between two machines. Node ships full ICU by default
and `LZ1019 icu-data-incomplete` catches a build with truncated data, but CLDR itself moves
between ICU releases, so pin the Node major across the apps and CI that share one generated
tree.

<Aside type="note">
The four `$`-prefixed imports (`$configure1`, `$plural1`, `$number1`, `$dateTime1`) are the
generated code's private ABI, versioned by the trailing digit and enforced by the JavaScript import
rather than by types: a stale tree from before a breaking change fails at link time because the
named export is gone. Apps never call them.
</Aside>
