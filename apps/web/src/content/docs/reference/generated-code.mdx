Everything on this page was written by `loclizr build` over the example app's catalogs, with
`groups: { errors: 'errors' }` in the config. The files are quoted as written, header included.

## The tree

JavaScript plus a hand-printed `.d.ts`, never `.ts`. Generated code must not inherit the host
tsconfig (`jsx`, path aliases, `strict`), must serve JavaScript consumers without `allowJs`, and
must not enter the app's typecheck graph, so the declarations are printed as text and `typescript`
is never needed to produce them. Every relative import carries an explicit `.js`, because this code
runs under Node during a server render.

One module per top-level key segment, not one file per message and not one flat file. Bundlers
already eliminate unused `export function`s inside a side-effect-free module, so per-message files
would buy nothing except thousands of files and unreviewable diffs, while a single flat module
would give up the deep import that is the only way to split by hand on React Native, where Metro
does not tree-shake. Root-level keys, ones with no dot, land in a module named `_root`.

Every file except the `.gitignore` starts with the same first line, byte for byte:

```js
// @generated by loclizr abi=1. Do not edit; run `loclizr build`.
```

That line is the token the prune step keys on. After writing, `build` deletes every file under
`outDir` that carries it and that this emit did not produce; a file without it is never deleted
and never overwritten, and is reported as `LZ1021 outdir-foreign-file` instead. Files are written
only when their bytes changed.

```txt title="src/loclizr/.gitignore"
*
!.gitignore
```

The tree is gitignored by default through that file, so your root `.gitignore` is never touched
and the artifact that lands in a pull request is the context record, not several hundred lines of
machine-written JavaScript. The `.gitignore` is written only when absent and is excluded from both
the write-if-changed comparison and `LZ5002`, so a team that would rather commit the tree deletes
it once and it stays deleted. `LZ5002 output-stale` then starts checking those files, since the
rule fires only for files that exist on disk.

The barrel is a sibling file rather than `messages/index.js`, so `./loclizr/messages` resolves in
bundlers and `./loclizr/messages.js` resolves under Node's ESM resolver with no file-versus-directory
ambiguity. It re-exports the store's three functions from `loclizr`, typed against `AppLocale`, and
the `declare module` block is what makes the package's own `getLocale()` and `useLocale()` return
that union too; `augmentLocale: false` omits the block and keeps the rest.

`groups.js` is deliberately not re-exported. Importing it is the explicit act of paying for that
group's tree-shaking.

`$l` is the resolver every message calls. The `$configure1` call that produces it carries no
`PURE` annotation on purpose: its result is load-bearing, every namespace module imports it, and
that is what keeps a bundler from dropping the call that registers the locale list with the store.
The frozen constants around it are annotated, so a locale array nobody reads can go.

`_formats.js` hoists every distinct option object the catalogs need into one shared module, so
two namespaces using the same currency format share one `Intl.NumberFormat` (the runtime caches by
object identity). Each constant is named `$f` plus a 64-bit hash of the canonical JSON of its
options rather than `$f1`, `$f2`, so adding a format anywhere in the project adds one line to this
file instead of renumbering every line below it. The empty object is what a bare `{count, number}`
and a plural's `#` resolve to.

## One message of each kind

Every message function has the same shape, `f(args, opts?)`, and its declaration carries the
source text as a doc comment. The first parameter is exactly the ICU argument set, so a message
with an argument literally named `locale` still compiles; the locale override is the second.

`de-AT.json` has no `nav.home`, so its arm shares the German string: that is the fallback chain,

`m.nav_home({ x: 1 })` a type error.

```js title="src/loclizr/messages/cart.js"
  const l = $l(opts)
  const n0 = args.count
  switch (l) {
    case 'de':
      if (n0 === 0) return `Dein Warenkorb ist leer`
      return `${$number1(l, n0, $f44136fa355b3678a)} Artikel in deinem Warenkorb`
    case 'de-AT':
      if (n0 === 0) return `Dein Einkaufswagerl ist leer`
      return `${args.count} Artikel im Einkaufswagerl`
    default:
      if (n0 === 0) return `Your cart is empty`
      switch ($plural1(l, n0, false)) {
        case 'one':
          return `${$number1(l, n0, $f44136fa355b3678a)} item in your cart`
        default:
          return `${$number1(l, n0, $f44136fa355b3678a)} items in your cart`
      }
  }
}
```

```ts title="src/loclizr/messages/cart.d.ts"
/** en: "{count, plural, =0 {Your cart is empty} one {# item in your cart} other {# items in your cart}}" */
export declare function cart_items(args: { count: number }, opts?: MessageOptions): string
```

Exact branches are tested before the category lookup, and `Intl.PluralRules` is only consulted
when some keyword branch renders differently from `other`: the German `one` and `other` bodies
are identical, so that arm never calls `$plural1`. The `#` goes through `$number1` with the empty option set, which is how
`m.cart_items({ count: 1234 })` renders `1,234 items in your cart`. The `de-AT` arm is the one
exception: it was `{{count}} Artikel im Einkaufswagerl` in an i18next file, and i18next
stringifies placeholders unformatted, so the conversion keeps `${args.count}` raw rather than
turning `1000 Artikel` into `1.000 Artikel` on import day.

The member property is the key minus the prefix and its dot, mangled. Typing is a mapped type, so
`errors.rate_limited({ seconds: 30 })` is checked exactly and `errors[code]` with `code: ErrorsKey`

types: the caller must pass a superset of every member's arguments, and `args` is required so
`errors[code]()` cannot compile and crash. That intersection is the cost `LZ4006` names at build
time for this very group. The literal carries `__proto__: null` so a member named `constructor`
cannot reach `Object.prototype`.

## How a call resolves its locale

Every function starts with `$l(opts)`. The resolver is bound to this tree's own `locales` and
`sourceLocale`, and it does one thing:

```ts
matchLocale(opts?.locale ?? getRawLocale(), locales, sourceLocale)
```

`getRawLocale()` is the store's raw requested tag: the active server request scope if one is
installed, otherwise the tag `setLocale` last stored, otherwise, where a `document` exists, the
value detected once on first read from the configured cookie and then `<html lang>`. It performs
no matching. The resolver matches the result against its own list by exact tag, then by dropping
subtags from the right, then falls back to the source locale. So `{ locale: 'de-CH' }` renders
`de`, `{ locale: 'sp' }` renders `en`, and a resolver still yields a declared locale when nothing
has been requested at all. Matching against the generated list rather than the store's is what lets
two generated trees with different locale sets each resolve correctly from one store.

The per-call `{ locale }` override is a correctness mechanism, not a convenience. A message call is
a plain function call with no subscription in it, so a component that calls `m.cart_items()` and
no hook re-renders when React re-renders it and at no other time. Two patterns re-render on a
switch: keying the root on `useLocale()` so the tree remounts, or passing
`{ locale: useLocale() }` at the call, which makes that component subscribe in place and keep its
state. The second also makes the locale a visible reactive dependency, which is what keeps a
memoizing compiler from caching the rendered string across a switch.

## What tree-shakes and what does not

Message modules are side-effect-free ESM with one `export function` per message, so an app that
imports the barrel and calls three messages ships three functions and the arms of every declared
locale inside them. `_formats.js` constants are annotated pure, so an unused format drops with the
last message that used it. `_locale.js` is retained by any message import, since `$l` is
load-bearing, and that is intended.

A group is the one thing that does not shake. `groups.js` builds a frozen object referencing every
member, so importing `errors` retains all three functions whether or not `errors.forbidden` is ever
named. Only that group pays, and only in an app that imports `./loclizr/groups`. The deep import
`./loclizr/messages/cart.js` is the escape hatch where a bundler tree-shakes nothing.

## Identifiers

`nav.home` becomes `nav_home`. Flat identifiers, never `m.nav.home()`, because a namespace object
literal retains every member and kills tree-shaking. Mangling, in order: normalize the key to NFC;
replace every character that is not `ID_Continue`, `$` or `_` with `_`, so a CJK or Cyrillic key
survives intact; prefix `$` if the result does not start with `ID_Start`, `_` or `$`; prefix `$`
if it is a reserved word, `default` or `then`, since a `then` export makes the module namespace
thenable and breaks `await import()`. An `identifiers` entry in the config replaces the whole
result and goes through the last two steps too. Namespace filenames are mangled the same way, so
a key such as `../x.y` cannot write outside `outDir`.

Two keys that mangle to one identifier are `LZ4001 identifier-collision`, fatal and never
auto-disambiguated with a counter, because a counter shifts when a key is inserted. An identifier
that is `__proto__`, `constructor`, `prototype`, one of the barrel's own exports (`locales`,
`sourceLocale`, `getLocale`, `setLocale`, `subscribe`), or that enters the `$` namespace is
`LZ4002 identifier-reserved`; so is a top-level key segment that would name `_locale`, `_formats`
or `_root`. Doc-comment text is escaped, so a source string containing `*/` cannot terminate the
comment early.

## Determinism

Emit sorts everything itself: messages by key, namespaces by mangled filename, hoisted formats by
name, group members by member property, groups by id, all by code point, and locale arms by tag
with the source locale always last under `default:`. It then runs itself a second time over a
reversed program and byte-compares. A difference is `LZ4005 nondeterministic-output`, fatal, and
its hint says to report it, because nothing in the project can be changed to clear it. That check
runs on every build, in memory.

<Aside type="note">
The four `$`-prefixed imports (`$configure1`, `$plural1`, `$number1`, `$dateTime1`) are the
generated code's private ABI, versioned by the trailing digit and enforced by the JavaScript import
rather than by types: a stale tree from before a breaking change fails at link time because the
named export is gone. Apps never call them.
</Aside>
