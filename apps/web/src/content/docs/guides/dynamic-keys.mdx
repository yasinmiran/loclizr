```ts title="src/loclizr/groups.d.ts"
export type ErrorsKey = 'forbidden' | 'not_found' | 'rate_limited'
export interface ErrorsArgs {
  forbidden: EmptyArgs
  not_found: EmptyArgs
  rate_limited: { seconds: number }
}
export declare const errors: Readonly<{
  [K in ErrorsKey]: (args: ErrorsArgs[K], opts?: MessageOptions) => string
}>
```

An error code arrives from an API and the page shows the message for it. `m['errors_' + code]`
throws the types away and hides the call from the usage scan; a group gives the lookup a record
and a key type instead.

```ts title="loclizr.config.ts"
export default defineConfig({
  locales: ['en', 'de', 'de-AT'],
  sourceLocale: 'en',
  groups: { errors: 'errors' },
})
```

A prefix matches on a dot boundary: `errors` captures `errors.forbidden`, never `errorsforbidden`.
The member name is the key minus prefix and dot.

## What is generated

```js title="src/loclizr/groups.js"
import { errors_forbidden, errors_not_found, errors_rate_limited } from './messages/errors.js'

export const errors = /*#__PURE__*/ Object.freeze({
  __proto__: null,
  forbidden: errors_forbidden,
  not_found: errors_not_found,
  rate_limited: errors_rate_limited,
})
```

`groups.js` and `groups.d.ts` land beside the barrel; above, the example app's `errors` group from
three keys.

- Null prototype, so a member named `constructor` cannot reach `Object.prototype`.
- Type names are the group name in PascalCase plus `Key` and `Args`: `nav.main` gives `NavMainKey`.

## Using it

```tsx title="src/App.tsx"
import { errors, type ErrorsKey } from './loclizr/groups'

const problems: readonly ErrorsKey[] = ['forbidden', 'not_found', 'rate_limited']

<Row index={4} value={errors[cart.problem]({ seconds: cart.seconds })}>
```

The example app types its state with the generated key union and indexes the record with it.

- Literal key: exact typing. `errors.rate_limited({ seconds: 30 })` compiles,
  `errors.rate_limited({ nope: 1 })` does not.
- Union key: a union of call signatures, which TypeScript calls with the intersection of their
  parameter types, so `errors[code]` needs every argument any member takes; `errors[code]()` and
  `errors[code]({})` are both errors, `seconds` being missing.
- Sound, and the tier's cost: one new member taking `{ retryAt }` breaks every existing dynamic
  call site.

The build says so the moment the members disagree. The example turns that rule off, because the
app exists to show the union call site:

```ts title="loclizr.config.ts"
  severity: {
    'ambiguous-source': 'error',
    // The errors group mixes a message that takes {seconds} with two that take
    // nothing, on purpose: the app shows the union call site that produces.
    'group-args-heterogeneous': 'off',
  },
```

With the rule at its default severity, the same build prints:

```text
warn  LZ4006  group-args-heterogeneous

  The group "errors" has members with different argument sets, so every dynamic call site must pass the union: seconds.

    errors.forbidden       takes no arguments
    errors.not_found       takes no arguments
    errors.rate_limited    takes seconds

  fix  Split the group by argument shape, or give the odd members bare {x} arguments.
```

Two groups, one for the argument-free codes and one for those carrying a retry, would silence it
without the `off`.

## An empty group

```text
error  LZ4004  group-empty

  The group "nope" matched no keys under the prefix "nope".

  fix  A prefix matches on a dot boundary, so "nope" captures "nope.forbidden" and never "nopeforbidden". Check the prefix.
```

A prefix that matches nothing is an error. The build still emits, so your typecheck has something
to point at: `NopeKey = never`, and every call through it is a type error too.

## Tree-shaking

- A group export names every member, so using the group retains all of them.
- Each export is a pure frozen object; a group the app never touches drops like any unused export.
- The barrel deliberately does not re-export `groups.js`, so an app pays only by importing the
  file. Messages called by name through the barrel are retained or dropped individually, as usual.

The usage scan reads both access forms: `errors.forbidden(...)` records a usage against that one
message, `errors[code](...)` against every member, so a message only ever reached dynamically
never shows as unused in the record.

## Content unknown at build time

A group needs its set known at build time. A string that does not exist when `loclizr build`
runs, a CMS article title or a message a user typed, is not a message and does not belong in a
catalog. A runtime `format()` for it would need an ICU parser in the browser, the one thing the
generated code promises never to ship; it is deferred, and would arrive as a separate entry if at
all.

<Aside type="note">
When the set is finite but the caller does not know it yet, a `select` is usually the better tool:
`{state, select, packing {...} shipped {...} other {...}}` is one message with one typed argument
rather than three messages and a lookup.
</Aside>
