One file per locale at `locales/{locale}.json`. The compiler reads it and never writes it.

```json title="locales/en.json"
{
  "nav": { "home": "Home", "cart": "Cart" },
  "cart": {
    "greeting": "Hi {name}, your cart is ready",
    "items": "{count, plural, =0 {Your cart is empty} one {# item in your cart} other {# items in your cart}}",
    "total": "Total: {amount, number, ::currency/USD}",
    "updated": "Updated {at, date, medium}"
  },
  "order": {
    "status": "{state, select, packing {Being packed} shipped {On its way} delivered {Delivered} other {Processing}}"
  },
  "terms": { "accept": "Read our <link>terms</link> before you continue." }
}
```

- An object is a level, a string is a message. `nav.home` becomes `m.nav_home()` in a module named
  `nav`.
- A key written already dotted, `"nav.home": "Home"`, flattens to the same path and collides with
  the nested form: `LZ1011 duplicate-key`.
- A `null` leaf is a missing translation and takes the fallback chain, like an absent key. In the
  source locale a `null` leaf removes the message from the tree with no diagnostic today; a target
  catalog that still carries the key then gets `LZ3003 extra-translation`.
- An array leaf is `LZ1010 catalog-shape-invalid`. The app wants the array; flattening it into
  `tips.0` and `tips.1` would hand it one message per item.

The grammar is decided per file. `{{` anywhere, or a key with a CLDR plural suffix, means i18next,
converted in memory. Everything else is ICU, which is this page.
[Importing i18next catalogs](/guides/i18next-import/) covers the other path.

## Arguments

| Written | Argument type |
| --- | --- |
| `{name}` | `string \| number` |
| `{count, plural, ...}` | `number` |
| `{at, date, ...}` | `Date \| number` |
| `{state, select, packing {...} shipped {...} other {...}}` | `'packing' \| 'shipped'`, the branch names without `other` |

The generated declaration is the contract, printed with the source text above it:

```ts title="src/loclizr/messages/cart.d.ts"
/** en: "Hi {name}, your cart is ready" */
export declare function cart_greeting(args: { name: string | number }, opts?: MessageOptions): string
/** en: "{count, plural, =0 {Your cart is empty} one {# item in your cart} other {# items in your cart}}" */
export declare function cart_items(args: { count: number }, opts?: MessageOptions): string
/** en: "Updated {at, date, medium}" */
export declare function cart_updated(args: { at: Date | number }, opts?: MessageOptions): string
```

## Plural and selectordinal

```json title="locales/en.json"
{
  "guests": "{count, plural, offset:1 =0 {Nobody is coming} =1 {Only you} one {You and # other} other {You and # others}}",
  "rank": "{place, selectordinal, one {#st} two {#nd} few {#rd} other {#th}} place"
}
```

```js title="src/loclizr/messages/_root.js (en arm)"
if (n0 === 0) return `Nobody is coming`
if (n0 === 1) return `Only you`
switch ($plural1(l, n0 - 1, false)) {
  case 'one':
    return `You and ${$number1(l, n0 - 1, $f44136fa355b3678a)} other`
  default:
    return `You and ${$number1(l, n0 - 1, $f44136fa355b3678a)} others`
}
```

Exact branches are tested first, against the value as passed. Then `Intl.PluralRules` picks a
keyword category and `#` renders the number through `Intl.NumberFormat`. With an `offset`, the
category and `#` use the value minus the offset; `=0` and `=1` still see the original.

- `other` is required. A plural without it is `LZ2004`, a select without it `LZ2005`, and the
  message is dropped from the output rather than guessed at.
- Categories come from `Intl.PluralRules` per locale, not from a table. A German catalog with a
  `zero` branch passes every syntax check and never renders it, because German never selects
  `zero`: `LZ3013 plural-category-unreachable`. The fix is the exact branch `=0`.
- The mirror case, a locale missing a category it needs, is `LZ3007`.

### The `many` category

```txt
warn  LZ3007  plural-category-incomplete  locales/es.json:1:23  es  cart.items

  es selects many for some values of {count}, and this plural has no branch for it.

  fix  add many {...} to {count, plural, ...} in locales/es.json
```

Spanish, French, Italian and Portuguese select `many` for the millions in current CLDR: on Node
22, `new Intl.PluralRules('es').resolvedOptions().pluralCategories` is `['many', 'one', 'other']`.
A plural translated with `one` and `other` alone passes every syntax check and raises `LZ3007`
once per plural message per such locale, at `warn`.

- Add `many {# ...}` to each message, mirroring `other`. For a message that counts things it is
  the same text twice.
- Or re-level `'plural-category-incomplete': 'off'` until the catalog is cleaned, then turn it
  back on.

The i18next importer does not synthesize the branch. `items_one` beside `items_other` folds into
a plural with those two branches and the same warning fires; an `items_many` key folds in like any
other suffix and clears it.

## Select

```json title="locales/en.json"
{ "order": { "status": "{state, select, packing {Being packed} shipped {On its way} delivered {Delivered} other {Processing}}" } }
```

The example app derives its state type from the generated signature instead of declaring it twice:
`type Delivery = Parameters<typeof m.order_status>[0]['state']`.

A translation that drops a branch is a warning (`LZ3008`). One that adds a branch the source lacks
is an error (`LZ3009`).

## Number and date styles

| Written | Intl options |
| --- | --- |
| `{n, number}` | `{}` |
| `{n, number, integer}` | `{ maximumFractionDigits: 0 }` |
| `{ratio, number, percent}` | `{ style: 'percent' }` |
| `{amount, number, ::currency/USD}` | the skeleton, resolved at build time |
| `{views, number, ::compact-short}` | `{ notation: 'compact', compactDisplay: 'short' }` |
| `{at, date}` or `{at, date, medium}` | `{ dateStyle: 'medium' }` |
| `{when, time, short}` | `{ timeStyle: 'short' }` |
| `{when, date, ::yMMMd}` | `{ year: 'numeric', month: 'short', day: 'numeric' }` |

A bare `{amount, number, currency}` is `LZ2002 icu-style-unknown`, because ICU carries no
currency code:

```text
error  LZ2002  icu-style-unknown  locales/en.json:14:11  en  usd

  "currency" is not a known number style.

  fix  ICU carries no currency code. Define formats.number.currency, or write ::currency/USD.
```

Any other style name is looked up in `formats.number` or `formats.dateTime` in
`loclizr.config.ts`, so `{amount, number, eur}` works once `eur` is defined there.

<Aside type="tip">
`formats.timeZone` is merged into every date and time style, which matters the moment a server
renders one. `LZ3011 date-without-timezone` exists for that case and ships off;
[Server rendering](/guides/server-rendering/) says when to turn it on.
</Aside>

## Markup

`<link>terms</link>` makes `link` a required argument and changes the return type: an array of
strings and whatever your handler returned, instead of a string.

```ts title="src/loclizr/messages/terms.d.ts"
/** en: "Read our <link>terms</link> before you continue." */
export declare function terms_accept<T>(
  args: { link: (chunks: readonly (string | T)[]) => T },
  opts?: MessageOptions,
): readonly (string | T)[]
```

- Tags nest: `<b><i>full</i> terms</b>` compiles to `args.b([args.i(['full']), ' terms'])`.
- A translator may renest tags freely. Only the set of tag names is compared across locales
  (`LZ3010`).
- Attributes inside a tag are not supported.
- `Parts` from `loclizr/react` renders the array, see [React](/guides/react/).

## Apostrophes

Quoting starts only when an apostrophe is followed by `{`, `}`, `<`, or `#` inside a plural
branch. `Don't` is fine as written.

| Written | Renders |
| --- | --- |
| `Don't` | `Don't` |
| `'{'` | `{` |
| `''` | `'`, always one literal apostrophe |

The record carries the canonical source in that quoted form: `Don't use '{' or '}' as literal text`
appears there as `Don''t use '{' or '}' as literal text` and renders as
`Don't use { or } as literal text`.

## Descriptions and placeholder notes

Notes for the translator live beside the source catalog, in `locales/en.meta.json`, never inside
it. A TMS (a translation management system, the web app translators work in) imports every leaf
of `en.json` as a translatable string, so a description written there ships as copy.
[Translation workflow](/guides/translation-workflow/) has the export rules.

```json title="locales/en.meta.json"
{
  "cart.items": {
    "description": "Badge under the cart icon on every page.",
    "placeholders": { "count": "Number of line items, not total quantity." }
  },
  "order.status": { "description": "Chip in the order list. Past tense." }
}
```

Both fields land in the context record. A note for a key that no longer exists is `LZ1015`.

The rule that makes descriptions worth writing is `LZ3012 ambiguous-source`: two keys share the
same source text and one of them has no description. Here `app.cart` lost its note while
`nav.cart` kept one:

```text
error  LZ3012  ambiguous-source  locales/en.json:5:14

  2 keys share the source text "Cart" and one has no description.
  A translator sees one string with no way to tell the meanings apart.

    app.cart    locales/en.json:5:14      no description
    nav.cart    locales/en.json:21:14     "Top navigation link that opens the cart page."

  fix  add descriptions in locales/en.meta.json:
         "app.cart": { "description": "" }
  or   turn the rule down in loclizr.config.ts:
         severity: { 'ambiguous-source': 'warn' }
```

<Aside type="note">
That rule ships at `warn`. `loclizr init` raises it to `error` on a fresh project, where it costs
nothing, and leaves the line commented out on an existing catalog, where the first build would
otherwise be a wall of shared "Save" and "Cancel" strings.
</Aside>
