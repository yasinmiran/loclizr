`loclizr init` prints four scripts and one CI step. The split between them is the whole design.

```json title="package.json"
"prepare": "loclizr build --no-fail",
"predev": "loclizr build --no-fail",
"prebuild": "loclizr build",
"pretypecheck": "loclizr build"
```

```yaml title=".github/workflows/ci.yml"
# loclizr check compares the committed context record against this tree.
# loclizr build would rewrite that record in the CI workspace and pass.
- run: npx loclizr check
```

| Hook | Runs | Why |
| --- | --- | --- |
| `prepare`, `predev` | `build --no-fail` | A working tree has to exist; one untranslated key must not stop `vite dev`. |
| `prebuild`, `pretypecheck` | `build` | Fails on an error. |
| CI | `check` | Compares the committed record instead of rewriting it. |

## build --no-fail

The flag changes the exit code and nothing else. Every diagnostic is still produced, printed and
counted.

- Reached the write step: exits 0 instead of 1.
- Wrote no output: still exits 1, since the next command would fail on a missing module anyway.
- Exit 2 is untouched: a build that could not run produced nothing to keep working with.
- `check` does not accept the flag. `check` is the gate.

## What check does

Everything `build` does, with no writes, plus two rules.

| Rule | Fires when |
| --- | --- |
| `LZ5002 output-stale` | A generated file on disk differs from what this run would write. |
| `LZ5003 record-stale` | The committed `locales/loclizr.context.json` differs from the one this tree produces. |

A fresh clone with the generated tree gitignored, the default, gives `LZ5002` nothing to compare,
so `check` needs no prior `build`:

```text
26 messages, 3 locales (source en), 0 errors, 1 warning
```

## The committed record

The record is a pure function of the catalogs, the meta sidecar, the scanned sources and the
config; it never reads its own previous value. Editing a source string changes that message's
`source` and `sourceHash`, and `check` fails until `build` has run and the rewritten record is
committed with the string change:

```text
error  LZ5003  record-stale  locales/loclizr.context.json

  `locales/loclizr.context.json` no longer matches the catalogs: the contract this build derived differs from the committed record.

  fix  run `loclizr build` and commit the record with the string change.
```

`build` runs the same comparison at `warn`, so a `prebuild` hook that quietly rewrote the record
still says so:

```text
warn  LZ5007  record-rewritten  locales/loclizr.context.json

  `locales/loclizr.context.json` was rewritten: the committed record's contract differs from the one these catalogs produce.

  fix  commit the rewritten record with the string change, so the context lands in the same pull request.
```

### What the gate compares

The contract: keys, ids, modules, kinds, source text and hash, descriptions, argument names and
types, plural and select shapes, markup tags. Add or remove a key, rename a placeholder, change a
description, and `check` fails.

Two fields are projected out of both sides first, each tried against the example catalogs.

- **Translator pull requests.** A German string edited in `de.json`, then a key deleted from it:
  neither raised `LZ5003`. The deletion raised `LZ3001 missing-translation` for the two locales
  that now fall back, the right error for it. Per-locale status is the record's `translations`
  array, outside the gate, because a batch of translations landing is not a change to the
  contract.
- **Usage churn.** A component calling `m.nav_home()` renamed and its file moved to another
  directory: `check` exited 0. The `usage` entries, file plus enclosing scope, sit outside the
  gate too; the next `build` rewrote them.

`build` still writes the whole file whenever any byte differs, so the committed record keeps its
coverage and render sites for whoever reads it, while the rule only ever compares the projection.

<Aside type="note">
Committing the generated tree, by deleting the self-ignoring `.gitignore` inside `outDir`, opts
`LZ5002` in: a translator's edit to `de.json` now changes `messages/nav.js` on disk in CI, and
that pull request fails `check` until someone reruns `build`. With the tree ignored, it passes.
</Aside>

## Warnings, and machine output

| Flag | Effect |
| --- | --- |
| `--max-warnings` | No cap by default, so warnings alone never fail a run. `--max-warnings 0` turns the example's one warning into exit 1 on `check`; `build --no-fail` still exits 0. |
| `--quiet` | Errors only, plus a summary line when warnings were dropped. |
| `--reporter json` | One object: diagnostics sorted by severity, code, file, locale, key and offset, summary last. |

```json
{
  "schema": 1,
  "diagnostics": [
    {
      "code": "LZ4006",
      "rule": "group-args-heterogeneous",
      "severity": "warn",
      "fatal": false,
      "message": "The group \"errors\" has members with different argument sets, so every dynamic call site must pass the union: seconds.",
      "hint": "Split the group by argument shape, or give the odd members bare {x} arguments.",
      "file": null,
      "locale": null,
      "key": null,
      "span": null,
      "related": [
        { "file": null, "locale": null, "key": "errors.forbidden", "span": null, "message": "takes no arguments" },
        { "file": null, "locale": null, "key": "errors.not_found", "span": null, "message": "takes no arguments" },
        { "file": null, "locale": null, "key": "errors.rate_limited", "span": null, "message": "takes seconds" }
      ]
    }
  ],
  "summary": { "errors": 0, "warnings": 1, "messages": 26, "locales": 3, "fellBack": [] }
}
```

`file` is always POSIX and relative to the project root, on every machine, so the sort order
matches between a laptop and a runner.

## Exit codes

| Code | Meaning |
| --- | --- |
| 0 | clean, or warnings only and at or under `--max-warnings` |
| 1 | at least one error, or warnings over `--max-warnings` |
| 2 | the tool could not run: invalid usage, invalid config, unsafe `outDir`, unwritable output |
