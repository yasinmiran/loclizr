`loclizr/react` exports three things. React is an optional peer dependency (18 or newer), and
nothing else in the package touches it, so an app that never imports this entry ships no React
binding.

```ts
useLocale(): Locale
useSetLocale(): (locale: Locale, options?: SetLocaleOptions) => void
Parts(props: { of: readonly (string | ReactNode)[] }): ReactElement
```

`Locale` is your declared union once the generated barrel has augmented it, so `useLocale()` in the
example app returns `'de' | 'de-AT' | 'en'`.

## useLocale

`useSyncExternalStore` over the store, with module-level function references, so nothing
resubscribes on render and there is no tearing. It is the only subscription in the library. A
message call is not one, and that fact drives every pattern below.

Outside production the hook also runs one effect: it compares `document.documentElement.lang` with
the resolved locale, assigns it when they differ, and warns once. There are two messages, one for a
missing attribute and one for a wrong one, and both point at the same fix, described under
[Server rendering](/guides/server-rendering/).

```text
loclizr: <html> carries no lang attribute, so a client with no cookie has nothing to read. Render lang from the Content-Language header withLocale sets.
loclizr: <html lang="en"> disagrees with the resolved locale "de". Render lang from the Content-Language header withLocale sets.
```

## useSetLocale

Returns the store's `setLocale`. It exists so a component can take the setter from the hook rather
than importing the generated barrel only for that; the example's `Switcher` calls `m.setLocale`
directly, and either is fine.

## Parts

A message with markup tags returns an array, not a string. `Parts` renders one:

```tsx title="src/App.tsx"
<p className="terms" id="terms">
  <Parts
    of={m.terms_accept({
      link: (chunks) => (
        <a className="terms__link" href="#terms">
          {chunks}
        </a>
      ),
    })}
  />
</p>
```

The whole component is `createElement(Fragment, null, ...props.of)`. Spreading the array as
positional children means React asks for no keys. No `'use client'` directive is emitted anywhere
in v0.1, so `Parts` can be called from a server component too; an app that needs the directive puts
it on its own file.

## The key-on-root pattern

Because a message call does not subscribe, a component that only calls `m.*()` re-renders when its
parent renders it and at no other time. The default answer is to key the tree on the locale at the
root:

```tsx title="src/main.tsx"
function Shop() {
  const locale = useLocale()
  const [cart, setCart] = useState(openingCart)
  return (
    <>
      <App key={locale} cart={cart} onChange={(patch) => setCart((current) => ({ ...current, ...patch }))} />
      <CourierNote />
    </>
  )
}
```

One `useLocale` call, and every string under `App` is recomputed on a switch with no per-component
discipline anywhere below. The cost is a remount: local state under the key is discarded, so an
open accordion closes and a half-typed form empties, and a virtualized list, which kept its scroll
offset in state, jumps back to the top. For most apps a language switch is a page-level event and
that is fine. State that has to survive goes above the key, which is why `cart` lives in `Shop`
and is passed down.

## The state-preserving alternative

A component that cannot afford the remount subscribes on its own and passes the locale into each
call:

```tsx title="src/CourierNote.tsx"
export function CourierNote() {
  const locale = useLocale()
  const [note, setNote] = useState('')
  return (
    <section className="note">
      <label htmlFor="note">{m.app_note({}, { locale })}</label>
      <textarea id="note" value={note} placeholder={m.app_notePlaceholder({}, { locale })} onChange={(event) => setNote(event.target.value)} />
      <p>{m.app_noteKeeps({}, { locale })}</p>
    </section>
  )
}
```

It re-renders in place and keeps `note`. It also has to keep the discipline: a message call inside
it that forgets `{ locale }` still reads the store and still renders the right language, but with
no visible dependency, which is where the next section comes in.

<Aside type="note">
The example app renders `CourierNote` outside the keyed `App` on purpose, so the two patterns can
be compared on one page: switch the language with text in the box and the text is still there.
</Aside>

## React Compiler

The hazard sits outside `useLocale`: `m.app_name()` reads mutable external state and takes no
arguments, so a memoizing compiler is entitled to cache its result for the lifetime of a component
instance. Both patterns above already answer it. The keyed root is sound because the compiler's
caches are per instance and a remount throws them away. The per-call form is sound because
`{ locale }` is a value the compiler can see change.

The keyed root has two holes, both documentation rather than structure. It does not reach a second
`createRoot`, such as a toast layer mounted separately. And it does not reach a string computed once
at module scope. The per-call override is the escape for both, and that, more than convenience, is
why it exists.
