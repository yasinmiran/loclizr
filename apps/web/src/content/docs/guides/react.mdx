```ts
useLocale(): Locale
useSetLocale(): (locale: Locale, options?: SetLocaleOptions) => void
Parts(props: { of: readonly (string | ReactNode)[] }): ReactElement
```

React is an optional peer dependency (18 or newer); nothing else in the package touches it, so an
app that never imports `loclizr/react` ships no React binding. `Locale` is your declared union once the barrel
has augmented it: `'de' | 'de-AT' | 'en'` in the example app.

## useLocale

`useSyncExternalStore` over the store with module-level function references: nothing resubscribes
on render, no tearing. The only subscription in the library; a message call is not one, which
drives every pattern below.

```text
loclizr: <html> carries no lang attribute, so a client with no cookie has nothing to read. Render lang from the Content-Language header withLocale sets.
loclizr: <html lang="en"> disagrees with the resolved locale "de". Render lang from the Content-Language header withLocale sets.
```

Outside production one effect compares `document.documentElement.lang` with the resolved locale,
assigns it when they differ, and warns once. Missing attribute or wrong one, the fix is under
[Server rendering](/guides/server-rendering/).

## useSetLocale

The store's `setLocale` from a hook, so a component need not import the generated barrel for the
setter alone. The example's `Switcher` calls `m.setLocale` directly; either is fine.

## Parts

```tsx title="src/App.tsx"
<p className="terms" id="terms">
  <Parts
    of={m.terms_accept({
      link: (chunks) => (
        <a className="terms__link" href="#terms">
          {chunks}
        </a>
      ),
    })}
  />
</p>
```

A markup message returns an array, not a string; `Parts` renders it. The whole component is
`createElement(Fragment, null, ...props.of)`, and positional children need no keys.

<Aside type="note">
v0.1 emits no `'use client'` directive, so `Parts` works from a server component too; an app that
needs the directive puts it on its own file.
</Aside>

## The key-on-root pattern

```tsx title="src/main.tsx"
function Shop() {
  const locale = useLocale()
  const [cart, setCart] = useState(openingCart)
  return (
    <>
      <App key={locale} cart={cart} onChange={(patch) => setCart((current) => ({ ...current, ...patch }))} />
      <CourierNote />
    </>
  )
}
```

A component that only calls `m.*()` re-renders when its parent does and at no other time. Key the
root on the locale and one `useLocale` call recomputes every string under `App` on a switch, with
no per-component discipline below.

The cost is a remount, which discards local state under the key:

- an open accordion closes
- a half-typed form empties
- a virtualized list that kept its scroll offset in state jumps back to the top

For most apps a language switch is a page-level event, which is fine. State that must survive goes
above the key: `cart` lives in `Shop` and is passed down.

## The state-preserving alternative

```tsx title="src/CourierNote.tsx"
export function CourierNote() {
  const locale = useLocale()
  const [note, setNote] = useState('')
  return (
    <section className="note">
      <label htmlFor="note">{m.app_note({}, { locale })}</label>
      <textarea id="note" value={note} placeholder={m.app_notePlaceholder({}, { locale })} onChange={(event) => setNote(event.target.value)} />
      <p>{m.app_noteKeeps({}, { locale })}</p>
    </section>
  )
}
```

A component that cannot afford the remount subscribes on its own and passes the locale into each
call; it re-renders in place and keeps `note`. A call that forgets `{ locale }` still reads the
store and still renders the right language, with no visible dependency.

<Aside type="note">
`CourierNote` is rendered outside the keyed `App` on purpose, so both patterns sit on one page:
switch the language with text in the box and the text is still there.
</Aside>

## React Compiler

The hazard sits outside `useLocale`: `m.app_name()` reads mutable external state and takes no
arguments, so a memoizing compiler is entitled to cache its result for a component instance's
lifetime. Both patterns already answer it:

| Pattern | Why it is sound |
| --- | --- |
| Keyed root | Caches are per instance, and a remount throws them away. |
| Per-call `{ locale }` | A value the compiler can see change. |

Two holes in the keyed root, documentation rather than structure: a second `createRoot`, such as a
separately mounted toast layer, and a string computed once at module scope. The per-call override
is the escape for both, and that, more than convenience, is why it exists.
