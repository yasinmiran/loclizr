import { Aside, Steps } from '@astrojs/starlight/components'

```ts title="src/loclizr/messages.d.ts"
export type AppLocale = 'de' | 'de-AT' | 'en'

export declare function getLocale(): AppLocale
export declare function setLocale(locale: AppLocale, options?: SetLocaleOptions): void
export declare function subscribe(listener: () => void): () => void
export { locales, sourceLocale } from './messages/_locale.js'
```

One store, in `loclizr`; the generated barrel re-exports its three functions narrowed to your
declared locales. `subscribe` takes a plain listener and returns its remover; `useLocale` is built
on it, and outside React you call it directly.

```tsx title="src/Switcher.tsx"
import { useLocale } from 'loclizr/react'
import * as m from './loclizr/messages'

const offered = [m.sourceLocale, ...m.locales.filter((tag) => tag !== m.sourceLocale)]

export function Switcher() {
  const locale = useLocale()
  const names = new Intl.DisplayNames([locale], { type: 'language' })
  return (
    <div className="switcher">
      {offered.map((tag) => (
        <button key={tag} type="button" aria-pressed={tag === locale} onClick={() => m.setLocale(tag)}>
          {names.of(tag) ?? tag}
        </button>
      ))}
    </div>
  )
}
```

`m.locales` is the frozen tuple `['de', 'de-AT', 'en']` and `m.sourceLocale` is `'en'`; a switcher
needs nothing else.

## How the locale is resolved

First match wins:

<Steps>

1. An active server request scope.
2. What `setLocale` stored.
3. Where a DOM exists, a lazily detected initial value: the cookie, then `<html lang>`, nothing
   else.
4. The source locale.

</Steps>

Matching is exact, then by cutting subtags: `de-CH` resolves to `de`. An unknown tag falls to the
source locale, so a cookie edited to `sp` renders English, never `undefined`.

<Aside type="note">
Detection never reads `navigator.languages` or `localStorage`: a server sees neither, and the
page would hydrate in a language it was not rendered in.
</Aside>

## Persistence

`setLocale('de')`, in order:

- writes a cookie named `locale` (`path=/`, one year, `SameSite=Lax`), the name following `cookie`
  in `loclizr.config.ts`
- sets `document.documentElement.lang`
- notifies subscribers

The cookie is the only channel a server can read back, hence the only persistence.
`{ persist: false }` changes the language for this page load only. With no `document`, React
Native included, the store updates in memory and notifies subscribers; nothing persists.

<Aside type="caution">
Inside a server request scope `setLocale` throws: changing a process-wide locale in the middle of
somebody's request has no correct meaning.

```text
loclizr: setLocale() cannot run inside a request scope. Pass { locale } per call instead.
```

[Server rendering](/guides/server-rendering/) has the per-request shape.
</Aside>

## The per-call override

```ts
m.cart_items({ count: 3 }, { locale: 'de' })   // "3 Artikel in deinem Warenkorb"
```

Every message function takes an options object second, and `{ locale }` there wins over the store
for that one call.

## What re-renders, and what does not

<figure class="diagram">

Message functions read the store at call time either way.](../../../assets/diagrams/language-switch.svg)

</figure>

`m.nav_home()` subscribes a component to nothing; generated code imports nothing from React. After
`setLocale('de')` a component that only calls messages shows German the next time its parent
happens to render it.

### Key the root on the locale

```tsx title="src/main.tsx"
function Shop() {
  const locale = useLocale()
  const [cart, setCart] = useState(openingCart)
  return (
    <>
      <App key={locale} cart={cart} onChange={(patch) => setCart((current) => ({ ...current, ...patch }))} />
      <CourierNote />
    </>
  )
}
```

`Shop` subscribes through `useLocale`; the `key` changes on a switch and `App` remounts with every
string recomputed. A remount discards local state below the key, so the cart lives above it in
`Shop`; anything in `App`'s own `useState` would be gone.

### Pass the locale per call

```tsx title="src/CourierNote.tsx"
export function CourierNote() {
  const locale = useLocale()
  const [note, setNote] = useState('')
  return (
    <section className="note">
      <label htmlFor="note">{m.app_note({}, { locale })}</label>
      <textarea id="note" value={note} placeholder={m.app_notePlaceholder({}, { locale })} onChange={(event) => setNote(event.target.value)} />
      <p>{m.app_noteKeeps({}, { locale })}</p>
    </section>
  )
}
```

`CourierNote`, outside the keyed subtree, subscribes itself and passes the locale into every call:
it re-renders in place and the note you were typing survives the switch.

The example app runs both on one page: keyed root for the bulk, per-call where state must survive.
[React](/guides/react/) has the React Compiler reason the second form exists at all.
